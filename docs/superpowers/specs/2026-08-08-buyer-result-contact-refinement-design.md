# 買方方向卡聯絡與結果頁精修設計

日期：2026-08-08  
正式站：https://buyer.tainanwei.com/

## 目標

依正式站的 8 個瀏覽器標記，精修結果頁與聯絡卡，使資訊更易讀、聯絡方式更實用，並讓「儲存需求照片」成為真正可下載的品牌圖片功能。保留既有六題流程、31 欄名單契約、送單去重、完整看屋清單、品牌與舊站隔離。

## 核准需求

1. LINE 按鈕改用正確加好友網址 `https://line.me/R/ti/p/%40tainanwei`，不再使用目前錯誤的 `oaMessage` 網址。
2. 聯絡欄位標示為「手機號碼 or LINE ID」，並真正接受兩種值：
   - 台灣手機：允許使用者輸入空白或連字號，送出前整理為 `09` 開頭的 10 碼數字。
   - LINE ID：接受 LINE 官方允許的半形小寫英數與 `.`、`-`、`_`；輸入大寫時轉為小寫。純數字輸入仍必須符合 10 碼手機，避免把錯誤電話誤判為 LINE ID。
   - 畫面提示：「手機輸入10碼，例09XX；LINE ID 可直接輸入」。
3. 桌機版稱呼與聯絡欄維持等寬、同高、同一基準線；手機版維持單欄堆疊，不製造水平捲動。
4. 結果標題固定分成兩行：
   - `先把生活與負擔對齊；`
   - `再挑真正值得看的房子。`
5. 結果狀態膠囊字級放大為現有的 1.5 倍，連同內距調整，仍保持清楚而不壓迫標題。
6. 聯絡卡的次要操作新增 `tel:0927617207` 撥打電話按鈕，保留回上一步與 LINE。
7. 「複製需求摘要」改成「儲存需求照片」，按下後真的產生並下載 PNG，不只是改文字。

## 資料與後端相容性

- 前端狀態與 payload 仍使用既有 `phone` key，避免新增第 32 欄或破壞既有去重、確認與舊資料讀取。
- 第 5 欄的資料語意擴充為聯絡方式，Apps Script 標題改為「手機／LINE ID」，欄數與順序維持 31 欄。
- Apps Script 與前端共用同一驗證規則：10 碼手機或合法 LINE ID。寫入前一律經公式安全處理並以文字保存。
- 既有 submission ID、lock 去重、status polling 與失敗後 snapshot 規則不變。

## 需求照片

- 由瀏覽器原生 Canvas 產生 1080×1350 PNG，不引入外部截圖函式庫或 CDN。
- 圖片使用目前核准的墨綠、暖白、金色顧問卡視覺，內容包括：品牌、結果狀態、兩行主標、目前方向、預算提醒、最優先 3 題與電話。
- 圖片不放稱呼、手機或 LINE ID，避免使用者分享圖片時外洩聯絡資料。
- 檔名為 `台南小魏-買房方向卡-YYYYMMDD.png`；成功後以既有 toast 告知「需求照片已儲存」。
- 若 Canvas 匯出失敗，顯示誠實錯誤訊息，不退回偷偷複製文字。

## 排版與操作

- 結果主標以兩個 block span 呈現，確保斷行位置固定，不依螢幕寬度碰運氣。
- 聯絡卡桌機以兩欄 grid 呈現，兩個欄位的標籤、輸入框與說明各自占固定列；手機 breakpoint 改為一欄並取消不必要的空白說明列。
- 四個次要操作在寬螢幕同列或自然換行；760px 以下改成等寬單欄，觸控高度至少 48px。
- 新增電話與 LINE 連結皆是原生 `<a>`；儲存圖片為原生 `<button>`，維持鍵盤與 focus-visible 支援。
